## 0. 结论

DSH 看板已经具备**可信的产品骨架**：令牌纪律、黑主按钮、0.5px 中性边框、浮层 elevation、列表/看板/抽屉/审批/批量选择/空加载错误基本齐备，且没有典型 AI 生成页面的紫色渐变和堆砌装饰。当前问题集中在**窄屏可用性、浅色主题可读性、视觉层级和状态反馈**，不是“重做视觉风格”。

| craft 维度 | 分数（1–5） | 判断 |
|---|---:|---|
| Typography | 2.5 | 字号/行高整体稳定，但页面标题 13px 小于卡片标题 14px；层级靠颜色而非字号，扫描路径偏弱 |
| Color | 2.5 | 令牌使用非常干净（组件 CSS 无直接 hex/rgb、无渐变）；浅色主题状态色与弱文本对比度不足 |
| Anti-AI-slop | 4.5 | 无紫色/渐变/玻璃拟态/营销字体；主色克制；问题主要是产品密度，不是审美俗套 |
| State coverage | 2.5 | 有 loading/empty/initial error/selection/approval/composer；SSE 断线无可见反馈，错误文案偏开发态 |
| Accessibility | 2.0 | 对比度、触摸目标 44px、窄屏 icon-only tab 可访问名有明确缺口；focus/keyboard 基础已具备 |
| **综合** | **2.8** | 基础工程与视觉骨架合格，先修可用性与可读性，再做层级与细节 |

优先级汇总：**P0 × 1，P1 × 10，P2 × 4**。建议分 3 批，每批 ≤6 项，先处理不改变信息架构的可用性修复，再动色彩与层级。

## 1. Craft 标尺

本审计把“craft”落在五个可检查维度上，避免“看起来不够高级”这种不可执行判断：

| 维度 | 5 分的样子 | 本次检查点 | 现状 |
|---|---|---|---|
| Typography | 页面/区块/卡片/元数据有明确层级；中文字体稳定；数字用 tabular；长文可读 | 页面标题 vs 卡片标题、抽屉标题、列头、meta 字号/字重、tabular figures | 标题层级倒置；body 稳定；关键数字已 tabular |

| Anti-AI-slop | 无营销站字体/紫色渐变/玻璃卡片/巨大圆角；密度服从信息任务 | 字体来源、渐变、raw color、阴影、圆角、装饰性图形 | 通过；无营销化装饰 |
| State coverage | loading/empty/error/offline/disabled/选中/审批已解决都有明确视觉 | 初始加载、搜索空态、初始加载失败、SSE 断线、禁用、选择模式、composer | 基本齐；SSE 断线静默；错误文案开发态 |
| Accessibility | 对比、焦点、可访问名、触摸目标、语义结构 | 对比度计算、390px 按钮/复选框尺寸、icon-only tab 名称、focus-visible | 对比、触摸、可访问名需修；focus/reduced-motion 基础好 |

## 4. 「不要改」清单

以下项已经符合 DSH 规范和产品判断，后续迭代不要为了“更高级”改掉：

1. **令牌与颜色纪律**：组件 CSS 只用 `--dsw-alias-*` / `--kb-*`；没有直接 hex/rgb（`tokens.css` 的 fallback 是主题镜像，属预期）；没有渐变、紫色、玻璃拟态。
2. **单一主色 + 黑主按钮**：黑底主按钮、白/灰表面、语义色只做状态点；不要引入第二个品牌色或营销渐变。
3. **字体来源**：保持 DSH 系统字体栈（`-apple-system / system-ui / PingFang SC…`）；不引入 Geist/Satoshi 等外部字体替换中文界面，只调现有 token 的字号/字重。
4. **边框 / 圆角 / 浮层**：中性 0.5px 边框；浮层无边框 + `--dsw-elevation-*`；卡片/列/控件圆角变量；不要加粗边框或大面积阴影。
5. **看板结构**：固定 4 列、待你确认列承载受阻/失败、列头计数、列内新建、拖拽换列；不要改成 5 列或加入侧边导航。
6. **列表结构**：状态/项目/优先级三档分组、组内折叠、宽屏行式布局；不要为了“卡片感”改成瀑布流。
7. **新建入口**：看板只用列头 `+`，列表只用 toolbar 主按钮；不要恢复顶栏全局“新建卡片”。
8. **批量选择结构**：工具栏“选择”、卡片/列表复选框、批量条（已选 N / 全选当前视图 / 清空 / 移动到 / 归档 / 取消）、拖拽禁用、Esc 退出；不要拆成多级菜单。
9. **审批结构**：单题/多题字段、统一备注与提交、逐题校验；保持信息完整，不要为了简洁删掉选项说明。
10. **开始推进层级**：待办 footer 次级 → 展开主按钮 → 菜单三级；不要提升为顶栏全局按钮。
11. **暗色主题、focus-visible、reduced-motion、键盘快捷键**：已实现且不是本次问题来源；保留现有 1px/2px focus ring 和动画降级。
12. **安全区**：`.kb-app--embedded` 用 `--kb-host-inset-top` 留出宿主左上控件；抽屉 footer/模态 footer 使用 `env(safe-area-inset-bottom)`；390 底部弹层。移动端与 iframe 安全区**不要移除或换成固定 padding**。
13. **加载/空/错误基本结构**：已有骨架、空态、初始错误页；不要加入营销式插画/大 hero/彩色渐变背景。
14. **tab 型数字**：metrics、耗时、时间已使用 `font-variant-numeric: tabular-nums`；不要为追求“柔和”去掉。

## 6. 验收与回归建议

- **视口**：1440×900（宽屏）、1024×768（紧凑，若实现批次 2 后补）、390×844（窄屏）、宿主 iframe（至少 1280 宽 + top inset）。
- **主题**：跟随/亮/暗三态，重点检查浅色状态色、批量条、审批风险；暗色不要回退。
- **状态**：首屏 loading、空结果、初始错误、SSE 断线、审批 resolved、选择 0/2 张、composer focus、拒绝禁用。
- **无障碍**：键盘 Tab 顺序、`aria-label`、`aria-selected`/`aria-pressed`、focus-visible、对比度、44px 热区、reduced-motion。
- **回归红线**：不改数据契约/接口、不改安全区、不引入外部字体/渐变、不新增顶栏全局新建入口、不改变审批/选择/开始推进的语义。
- **测量方式**：本审计用 Chromium CDP 计算 computed style 与对比度；建议实现批次 1 后把同样的测量脚本纳入视觉回归（可另建 task，不在本轮）。

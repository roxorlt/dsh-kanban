# DSH 看板 · 设计系统（v2，2026-10-21）

> 交付：`design/mockup.html`（单文件可交互高保真）、`design/screens/01–20`（状态截图）、`design/lint/`（组件样式抽取与令牌 lint）。
> 锚定 DSH `dsh-v0.1.5-rc.2` 设计令牌与 `dsh-ui-spec`；产品决定见 §10.3「已拍板」。

## 1. 设计目标与原则

看板是 **Agent 工作状态的可视化控制面**，不是传统任务管理工具：会话自主推进，人只在授权、方案选择、讨论三类节点介入。界面要安静、可扫读，把「需要人」的卡片推到眼前。

| # | 原则 | 落地 |
|---|---|---|
| 1 | 克制 | 一屏最多两种强调色（待你确认琥珀、会话活动蓝）；除审批与主按钮外不出现大面积填充色；动效只用于状态变化与浮层进入 |
| 2 | 发丝线 | 卡片、列、分隔线一律 `0.5px` 中性实线；状态色边框保持 `1px`；不用粗边框划分层级 |
| 3 | 浮层用阴影 | 菜单、筛选浮层、抽屉、底部弹层、Toast、Modal、二次确认全部 `border: 0` + `--dsw-elevation-*`，不叠加描边 |
| 4 | 主按钮黑 | 主操作（提交选择、新建、保存）用 `--dsw-alias-button-primary-fill`，不用业务蓝 |
| 5 | 密度优先 | 13px 正文 + 11px 元信息；折叠卡片承载 80% 信息；审批选项例外——必须完整展开 |
| 6 | 状态不只靠颜色 | 每个状态点有中文状态词；受阻/失败有原因文案；审批有图标、问题与每个选项说明 |
| 7 | 会话是主体 | 运行中的实体是「会话」；DSH Agent 只出现在时间线 actor 与消息发送者语境 |

## 2. 信息架构

### 2.1 术语

| 术语 | 含义 | 界面位置 |
|---|---|---|
| 会话（Session） | 执行卡片的工作单元；一个卡片可绑定多个会话，其中一个是主会话 | 运行中计数、会话列表、回复目标、时间线 actor |
| Agent | 会话内的执行者，仅作为 actor（谁写的/谁做的） | 时间线节点、消息 meta |
| 卡片（Card） | 看板最小单位；承载状态、摘要、动作、审批、素材与会话绑定 | 四列 |
| 审批（Approval） | 需要人选择的问题：单选/多选 + 选项说明 + 备注 | 待你确认卡片、详情 |
| 未归档卡片 | 未归档的卡片总数（`archived=false`），头部计数口径 | 顶栏 |
| 待你确认 | 包含 `needs_you`、`blocked`、`failed` 三种状态所在列（4 列制，不单独开列） | 第三列 |

### 2.2 四列与卡片五层

四列固定：**待办 Backlog / 进行中 Running / 待你确认 Needs you / 已完成 Done**。`blocked`、`failed` 状态归入「待你确认」列，就地用状态点 + 原因表达；`done` 与 `canceled` 归入「已完成」。

卡片信息分五层：

| 层 | 字段 | 位置 |
|---|---|---|
| 身份 | 状态点、标题 | 首行 |
| 意图 | 一句话摘要（2 行截断，竖屏 3 行） | 标题下 |
| 现在 | 当前动作 / 最近节点 + 耗时 | 摘要下 |
| 属性 | 优先级、项目、标签；状态、耗时、工具调用、搜索、会话入口 | 属性行 + 页脚 |
| 结果 / 决策 | 审批问题、全部选项与说明、备注、提交/驳回；失败卡的重试 | 卡片底部（仅待你确认） |

### 2.3 三档信息密度

| 档位 | 触发 | 显示 | 高度预算 |
|---|---|---|---|
| 折叠 | 默认 | 状态点 + 标题 + 摘要 + 当前动作 + 属性行 + 页脚；审批卡显示完整问题、全部选项、备注和提交按钮 | 审批卡约 360–520px，普通卡 144–190px |
| 展开 | 点卡片非交互区（含标题）/ 箭头 / Enter / Space | 折叠态 + 最近 3 条重要节点 +“加载更早” + 紧凑媒体行 + 内联回复 | 展开区最大高度 360px（竖屏 46dvh），内部滚动 |
| 详情 | 详情入口 / O / 双击卡片 / 会话图标 | 完整属性（含执行会话、执行目录）、全量节点、会话列表与线程、回复目标、审批、编辑 | 右抽屉 `clamp(380px,34vw,460px)`；竖屏底部弹层 ≤92dvh |

> 折叠态必须能完成“看懂问题 + 提交选择”，不得把选项或说明藏进展开层。

### 2.4 自主移动与人工介入

```mermaid
%%{init: {"flowchart": {"curve": "linear", "htmlLabels": false, "nodeSpacing": 50, "rankSpacing": 60}}}%%
flowchart LR
  A[会话自主执行] --> B[卡片自动移动]
  B --> C{需要人工介入?}
  C -->|授权| D[待你确认]
  C -->|方案选择| D
  C -->|讨论| D
  D --> E[提交选择或驳回]
  E --> F[写入会话]
  F --> B
```

- 提交选择：按所选选项的 `outcome` 落到进行中 / 待办 / 已完成；驳回固定回待办。结果写入会话（全文），看板只追加摘要节点。
- 每次列变更、审批、回复都追加时间线节点；时间线是追溯依据。
- 人工把卡从其他列拖进「待你确认」时，自动生成通用确认请求（标题「需要你确认：{卡片标题}」、选项「继续 / 停止」），并弹出可编辑的确认请求弹窗。

### 2.5 审批模型

对齐 DSH `user-questions` / `kanban_request_approval`：

```ts
{
  title: string, detail: string, multiSelect: boolean,
  options: [{ id, label, description?, tone: 'primary'|'danger'|'ghost', outcome?: 'running'|'backlog'|'done' }]
}
```

- **所有选项与说明在卡片内完整展示**（不折叠、不截断）；单选用 radio，多选用 checkbox。
- 备注可选；提交后完整文字写入会话，看板只留摘要节点。
- 驳回是“选择 danger 选项”的快捷路径；有 danger 选项才显示驳回。
- 多选至少选 1 项，否则内联 toast 并聚焦第一个选项。
- 审批通过后卡片按 outcome 回到 `进行中`（默认），不直接进入已完成；由会话完成后自行移动到已完成。

#### 2.5.1 多问题审批（对齐 DSH `ask_user_question`）

一个审批可包含多个问题；结构与 DSH `ask_user_question` 对齐：

| DSH 字段 | 看板 UI | 说明 |
|---|---|---|
| `questions[]` | 卡片内按题分组，全部展示 | 不折叠、不分页；一屏放不下时随列/抽屉滚动 |
| `header` | 题目标签（11px caption，如「发布渠道」） | 可空；空则只显示问题 |
| `question` | 问题正文（12px 500） | 每题一个 fieldset，带序号「1 / 3」 |
| `multi_select` | `单选` / `多选` 徽标 + radio/checkbox | 多选至少选 1 项 |
| `options[]` | 全部选项 + description | 与单问题审批同款选项卡片，不截断 |

- **统一提交**：所有题共用一个备注输入 + 一个「提交全部回答」按钮；提交前校验每题都有选择，缺哪题就聚焦哪题并 toast 提示。
- **回答序列化**：`answers[questionIndex] = optionId[]`；写入会话的消息按「题目标签：选项、选项」拼接为全文，看板节点只写摘要。
- **行首快捷动作**：多问题审批行不提供快捷批准，行首快捷动作只显示「详情 >」，进入卡片/详情逐题回答。
- 多问题审批不提供「编辑确认请求」（人工编辑仅适用于单问题模板）；拖入待你确认生成的是单问题默认模板。
- 问题数量建议 ≤4、每题选项 2–4 个；超过时拆卡或改用多张审批卡。

### 2.6 会话与同步

- 详情抽屉展示卡片绑定的全部会话：主会话徽标、运行中状态、`设为主会话`、`打开`。
- 回复目标下拉默认主会话；可切换后回复。
- 同步粒度（已拍板）：
  - **看板 → 会话**：用户提交审批、回复时发送全文。
  - **会话 → 看板**：Agent 只通过工具写摘要节点（界面上节点带「摘要」标记），不镜像全文，避免卡片变成聊天记录。
- 同义同步文案只保留在 Composer 下方一处：`全文写入所选会话；Agent 工具写回看板的只是摘要节点。`
- deep link 提案 `dsh://session/<sessionId>#<cardId>` 需宿主支持，v1.1 前以“面板内打开会话 + 卡片 URL hash”兜底。

### 2.7 重要节点、素材、已完成

- 时间线默认最近 3 条，提供「加载更早的 N 条」；展开区限高内部滚动，详情抽屉展示全量。
- 非文字素材不内联大图，使用紧凑媒体行：缩略图 + 数量（截图/录屏/报告/文件）+「在会话中查看」。
- 已完成列看板只渲染最近 5 张 +「查看全部 N 张 / 收起」；列表视图已完成分组默认折叠，展开后先显示 5 条 +「加载更多（剩余 N 张）」。
- 卡片菜单的删除语义为**归档**（可从撤销 Toast 恢复），对应头部“未归档”计数。
- **自动归档（v1.1）**：`done` / `canceled` 卡片在完成 30 天后自动归档。自动归档只改变可见性，不删除数据：卡片绑定、会话、审批结果与时间线保留，可通过归档视图找回；归档后不计入“未归档卡片”数。看板已完成列底部与帮助浮层均提示「已完成卡片 30 天后自动归档」。
- **动作文案统一**：所有详情入口固定为「详情 >」（卡片展开区、列表展开区、卡片菜单），不再混用「详情」「打开详情」「查看详情」；chevron 属于文案的一部分，不单独再加图标。

### 2.8 开始推进与待办语义（v1.1）

**开始推进**是待办卡片唯一的一级启动入口，只出现在 `status=todo`（待办列）：

| 层级 | 位置 | 形态 | 触控 |
|---|---|---|---|
| 主 | 卡片展开区（exp-head 下） | 黑底主按钮 + play 图标 +「开始推进」，旁注「启动或续接『主会话』」 | 桌面 30–32px；竖屏 36px |
| 次 | 折叠卡片 footer | 白底发丝线次级按钮 + play 图标 +「开始推进」（紧凑/竖屏显示「开始」） | 桌面 22px；竖屏 28–32px（热区 ≥36） |
| 三级 | 卡片菜单 | 菜单项「开始推进」（play 图标） | 菜单行 30px |

行为：

- 点击后**乐观地**把卡片从待办移到进行中，启动或续接主会话（多会话取主会话），并追加「你点了开始推进」节点；按钮随状态离开待办而消失。
- embedded：通过宿主桥确保/创建会话并发送启动提示；**standalone 预览**没有桥时降级为「预览模式已模拟启动会话」toast，不报错，仍允许演示。
- 启动失败：回滚到待办、保留原状态与节点，toast「启动会话失败 · 卡片已回到待办」，可重试；不得留下半启动的进行中卡。
- 无绑定会话：打开会话选择器（或按当前工作区新建），选中后再推进；v1.1 设计稿用已有绑定演示。

**待办回复不自动改状态**：在待办卡片上回复会话，只写会话与时间线，不移动卡片、不开始执行；Composer 提示固定为「回复全文写入所选会话；待办卡片不会因回复自动改变状态，需要时点『开始推进』。」`needs_you` 的讨论回复仍按原规则移入进行中。

### 2.9 新建卡片建议字段与无会话补建（v1.2）

**新建卡片（create）**在主表单里增加「工作区与目录」「关联会话」两组建议字段：

| 字段 | 控件 | 默认/建议规则 |
|---|---|---|
| 工作区 | 原生 select（名称 · 分支） | 默认当前工作区；切换后**自动回填** cwd（工作区根目录）与项目建议；不覆盖用户已手动改过的目录，仅在切换工作区时回填 |
| 执行目录 cwd | 输入框 + 推荐目录 chips | 路径可编辑；chips = 工作区根目录 / 常用子目录；点击 chip 写入 cwd；空值阻止提交并聚焦 |
| 所属项目 | select，带建议排序 | 当前工作区项目置顶并标「（当前工作区）」，随后最近使用（标「（最近）」），其余按名称；用户可改 |
| 关联会话 | 单选列表（新建 + 推荐会话） | 新建置顶；目标列为进行中时默认选中新建并显示「默认」；其他列默认选推荐会话；每行显示标题、推荐/运行中徽标、目录 |

**会话建议排序**：新建选项置顶；已有会话按「推荐（匹配工作区/项目且最近使用）→ 运行中 → 其他」排序。推荐徽标只给已有会话；新建在 running 目标下用「默认」而不是「推荐」，避免两个“推荐”冲突。

**默认与 CTA**：
- 目标列 = 进行中：默认「新建会话」，提交按钮「创建并启动」；若用户改选已有会话，按钮「创建卡片并绑定」。
- 目标列 = 待办 / 待你确认 / 已完成：默认选推荐会话（没有则新建），按钮「创建卡片并绑定」或「创建卡片」。

**空态与降级**：
- 没有工作区：文案「还没有工作区；先选择一个目录作为工作区。」并禁用会话建议。
- 没有会话：文案「没有可关联的会话；默认新建，创建后可绑定。」新建仍可选。
- 没有项目建议：select 可手动选择/保留当前值，不阻塞创建。
- 独立预览（无宿主桥）：底部固定提示「独立预览模式：不会创建真实会话；提交后模拟创建并写入时间线。」提交只模拟，不报错。

**详情抽屉无会话**：`running` 卡片显示警示「卡片正在进行中，但没有绑定会话」+「状态和消息暂时无法回写；先选择工作区/目录，再创建会话。」；内联表单同样包含工作区、cwd、推荐目录 chips，按钮按状态为「创建并开始处理」（running）或「创建并绑定」（其他）；创建完成前不显示回复 composer / 会话 tab。

## 4. 字体、间距、圆角、阴影、动效

### 4.1 字体层级

| 角色 | 令牌 | 规格 | 用例 |
|---|---|---|---|

### 4.2 间距、控件、动作区

- 间距阶梯 `4 / 6 / 8 / 10 / 12 / 16 / 20 / 24`；卡片内 gap 4–10，区块 16–20。
- 控件高度：icon 24–28；次级按钮 28；工具栏 32；主按钮 34–36；审批按钮桌面 30 / 竖屏 40；触控主决策热区 ≥44。
- **列表行快捷动作区（折叠行）**：批准/驳回/重试固定宽 64px（紧凑档 56px，竖屏 72px×32px 高）；同一行内右对齐成簇，放在指标与详情入口之间；竖屏换行到行尾并左对齐。动作区不参与省略与收缩，标题/摘要先让位。
- **列表展开区的审批动作行（默认左对齐）**：备注在上、按钮在下；`驳回` / `提交选择`（或 `提交全部回答`）靠左排列，每个按钮固定 72–96px 宽、不拉伸、不横通栏，不随容器宽度变化。`?listActions=right` 提供右对齐对照；**看板卡片内审批动作保持右对齐**（看板卡片的阅读顺序是“信息→备注→右下方决定”，列表展开区的阅读顺序是“行→详情→左下决定”，两者刻意不同）。行展开后隐藏行首快捷动作簇，避免同一动作重复出现。
- **三态主题控件**：顶栏右侧按钮按「跟随系统 → 亮色 → 暗色」循环，图标 + 文字标签（跟随/亮色/暗色）；`T` 同效。跟随系统时监听 `prefers-color-scheme` 与宿主 themeMode；手动选择覆盖当前主题，正式版持久化到 localStorage，embedded 默认跟随宿主。
- 看板列：列宽 ≥280（宽屏）/ ≥240（紧凑）/ 300（横向滚动）；列间距 16 / 12；列内卡片间距 10–12。
- 抽屉宽度 `clamp(380px, 34vw, 460px)`；底部弹层最大高 92dvh，`min-height: 42dvh`。
- **抽屉头部**：首行是 kicker（看板 · 状态 · 项目）+ 标题（左）与编辑/归档/关闭（右）；摘要（若有）独占第二行，宽度与正文内容一致（1440px 428、1100px 348、390px 358，右边缘与 chips/元数据对齐），长串 `overflow-wrap: anywhere`。标题列宽度与操作簇位置不因摘要在场而改变。

### 4.3 圆角

列 14；卡片/列表组 12；浮层 10；Modal 16；底部弹层 16（上两角）；控件 8；徽标 5。全圆（`50%` / `99px`）必须配 `corner-shape: round`；普通圆角由全局 `superellipse(1.5)` 平滑。

### 4.4 阴影与动效

- 卡片不用阴影，只用发丝线 + 悬停底色；菜单/浮层 `elevation-panel`；抽屉/Modal/确认框 `elevation-prominent`；唯一的 `shadow-lv1` 用于分段控件选中指示。
- 时长：hover/颜色 100ms；展开、Toast、抽屉淡入 200ms；抽屉/底部弹层滑入 300ms；`prefers-reduced-motion` 下全部压到 0.01ms，呼吸点静默。
- 展开区内部滚动不触发页面滚动；抽屉/弹层打开时焦点圈定。

## 6. 响应式

断点按应用窗口宽；看板在 DSH 主区内按容器自适应（`ResizeObserver` 写 `data-layout`，尺寸与下表一致）。

| 断点 | 列布局 | 列宽 / 间距 | 卡片密度 | 详情 | 触控 / 动作区 |
|---|---|---|---|---|---|
| **≥1440** | 4 列并排 | 280–340 / 16 | 完整：项目 + 2 标签，列英文副标可见 | 右抽屉 380–460 | icon 24–28；动作固定 64px |
| **1100–1440** | 4 列压缩 | ≥240 / 12 | 隐藏第 2 个标签、列英文副标；项目保留 | 右抽屉 | icon 28；动作 56px |
| **720–1100** | 4 列横向滚动（触摸板自由横滚 / 触摸设备按列吸附），一屏约 2–3 列 | 300 / 12 | 摘要 2 行；列表隐藏项目文本；状态栏隐藏 | 右抽屉 | icon 28–32；动作 56px |
| **<720 竖屏** | 顶部分段控件（4 列 + 计数）+ 单列 | 全宽 / 12 | 摘要 3 行；审批选项与按钮全宽；列头保留 | **底部弹层** ≤92dvh | 主决策热区 ≥44（视觉 40）；动作 72×32 |

- 桌面 shell：侧栏 52px + 主区；主区 padding 20–24；列内滚动、看板不整页滚动。
- 横向滚动手势：触摸板横滑与 Shift + 滚轮在整块看板（卡片、列体、列体空白、列头、列间隙）都生效，由 `useBoardWheelScroll` 统一接管；一次手势锁定单一轴向，不会同时横滚 + 竖滚；看板无横向溢出时不接管。720–1100px 下精细指针取消按列吸附（proximity 吸附会把每帧小横滑弹回原位），触摸设备保留吸附。

## 7. 交互规范

### 7.1 新建入口（收敛）

- 看板视图：**只有列头 `+` 与列底「新建卡片」**；顶栏不提供新建。
- 列表视图：**只有工具栏「新建卡片」**；分组头不提供新建。
- 新建弹窗解释三类信息：**项目**=逻辑分组、**标签**=自由筛选、**执行目录 workspaceId/cwd**=执行上下文；默认继承当前会话与工作区，可在详情中更换。

### 7.2 拖拽与换列

- 桌面 HTML5 拖拽：卡片 45% 透明、目标列 9% 业务蓝底、插入位置 2px 蓝线；松手写入状态、列变更节点与 Toast。
- 折叠列是合法投放目标，投放后展开；筛选状态下按当前可见顺序计算。
- 人工拖进「待你确认」→ 生成默认确认请求 → 弹出审批编辑器。
- 键盘替代：`Alt + ←/→` 换列、`Alt + ↑/↓` 列内排序；`aria-live` 播报。
- 批准结果：按所选选项 `outcome` 落到进行中/待办/已完成；驳回回待办；受阻/失败保持原状态直到人处理。

### 7.3 列表分组与已完成

- 分组：按状态（默认）/ 项目 / 优先级；切换后保留筛选、搜索与展开状态。
- 已完成：看板列只渲染最近 5 张 + 查看全部 N / 收起；列表完成组默认折叠，展开后 5 条 + 加载更多（剩余 N）+ 收起。
- 折叠行的快捷动作：批准/驳回/重试固定宽、右对齐；窄屏换行左对齐；行内快速批准使用默认主选项，完整选项仍在展开区/详情。
- 展开区的审批动作行：默认左对齐（备注在上、按钮在下、固定 96px 不拉伸）；`?listActions=right` 对照右对齐；看板卡片内审批仍右对齐。展开行隐藏行首快捷动作簇，避免重复。
- 多问题审批行只显示「详情 >」，不提供一键批准（必须逐题回答）。
- 所有详情入口统一「详情 >」。

### 7.4 展开、节点、素材

- 点卡片非交互区（标题、摘要、当前动作、属性行、页脚状态）或箭头、按 `Enter` / `Space` 展开或收起最近 3 条节点；展开区内部与审批面板内的文字点击不折叠卡片（避免阅读、作答、拖选文字时误触）；「加载更早的 N 条」每次 +5；展开区最大高度内部滚动。
- 素材只显示紧凑媒体行，点击「在会话中查看」跳到会话 tab；不在卡片内嵌大图。
- 列表行与卡片同构：点击行主区（标题、摘要、meta）展开/收起，按钮不触发展开；双击卡片或列表行打开详情。

### 7.5 会话

- 会话图标 / 「会话」按钮打开详情会话 tab；会话列表显示主会话、运行状态、`设为主会话`、`打开`。
- 回复目标选择默认主会话；`设为主会话`立即更新卡片页脚会话入口与回复默认目标。
- 看板→会话全文；会话→看板摘要节点（带「摘要」标记）；同一 Composer 一处解释。

### 7.6 关闭、草稿与焦点

- 弹窗/抽屉支持蒙层点击与 Esc 关闭；关闭前检查脏草稿：新建表单、审批编辑器、详情编辑、未发送回复、审批备注。
- 有脏草稿 → 确认框「放弃未保存的修改？」；`继续编辑`保留内容，`放弃修改`关闭；确认框本身 Esc/蒙层=继续编辑。
- 焦点：抽屉打开聚焦关闭按钮并圈定，关闭后回原卡片；`:focus-visible` 2px 业务蓝 outline；Toast/操作通过 `aria-live` 播报。

### 7.7 SSE 与错误

- 实时更新走 SSE，**没有手动刷新按钮**；工具栏显示会话运行中数量与 SSE 状态。
- 断连时顶栏下方出现错误条：「实时同步中断…」+ `重试` + 关闭；重试成功后状态恢复。任务失败卡的重试只在卡片/详情，不与全局刷新混淆。
- 移除了「Agent 自主推进」演示开关：自主性属于会话层，不是全局开关；如需暂停应走 DSH 会话控制。

### 7.8 快捷键

`⌘K` / `/` 搜索；`N` 新建；`B` / `L` 看板/列表；`T` 明暗；`Enter` / `Space` 展开收起；`O` 详情；`Alt+←/→` 换列；`Alt+↑/↓` 列内排序；`Esc` 关闭当前浮层（确认框 → 菜单 → 弹窗 → 抽屉）。

### 7.9 主题（跟随 / 亮 / 暗）

- 顶栏主题按钮三态循环：跟随系统（默认）→ 亮色 → 暗色；点击或 `T` 切换，显示当前模式图标与文字。
- 跟随系统：读取 `prefers-color-scheme`；embedded 下默认跟随宿主 `themeMode`；系统/宿主变化时即时更新。
- 手动选择覆盖当前主题；正式版写入 localStorage，下次启动恢复；mockup 用 `?themeMode=auto|light|dark`（`?theme=dark` 为旧别名），不持久化。
- 主题只切换 alias 令牌解析，不出现硬编码暗色表；所有浮层、状态色、阴影同步跟随。

### 7.10 批量选择（v1.1）

- **入口**：工具栏「选择」（看板/列表均可用）；进入后普通工具栏替换为批量条，清空当前展开态并关闭浮层。
- **勾选**：卡片与列表行显示复选框；点击卡片/行任意非交互区切换选中；键盘聚焦卡片后 Enter/Space 切换；选中态用业务蓝描边 + 底色。
- **禁用项**：拖拽（原生拖拽 + 键盘换列）、展开、详情/菜单、审批与回复操作全部禁用；行首快捷动作隐藏，避免与批量操作冲突。
- **批量条**：`已选 N` / `全选当前视图`（已全选时变为「取消全选」）/ `清空` / `移动到 …` / `归档` / `取消`。0 选时移动与归档禁用。
- **全选当前视图**：按当前筛选/搜索后的可见卡片计算；竖屏看板仅统计当前激活列，避免误选不可见列。
- **移动到**：批量换列；目标为「待你确认」时为每张卡生成默认确认请求（不逐张弹编辑器）。
- **归档**：移除选中卡片并给一次撤销 Toast；不影响会话绑定与审批记录。
- **退出**：`取消` 或 `Esc`；退出后清空选择、恢复工具栏与拖拽；状态栏/批量条给出操作播报。

### 7.11 自动归档（v1.1）

- 完成（`done`/`canceled`）后 30 天自动归档；看板已完成列底部展示「已完成卡片 30 天后自动归档」，帮助浮层补充完整说明。
- 自动归档不等于删除：卡片与会话的绑定、审批结果、时间线均保留，可从归档视图找回；归档卡片不计入“未归档卡片”数，也不再出现在默认四列。
- 手动归档（卡片菜单/批量归档）与自动归档共用同一“归档”语义；手动归档提供撤销 Toast，自动归档在设置/帮助中说明，不打断当前操作。

### 7.12 开始推进（v1.1）

- 入口层级：折叠 footer 次级（低干扰，适合扫读时快速启动）、展开区主按钮（明确行动）、菜单三级（不占视觉）。
- 只对待办 `todo` 出现；进入进行中后立即消失，避免重复启动。
- 点击：乐观移动 + 节点 + Toast；embedded 启动/续接主会话；standalone 预览降级为模拟 toast；失败回滚待办并提示重试。
- 多会话取主会话；无会话时先选择/新建会话；移动端主按钮 36px、footer 次级 ≥36 热区。
- 与「批量选择模式」互斥：选择模式隐藏开始按钮；与拖拽不冲突（先开始，再拖列）。

### 7.13 会话 → 看板跨面板导航（v0.5.1 更新）

- **默认不展示**任何常驻入口；只有同时满足以下条件时，在**输入框上方**出现一枚轻量气泡：
  1. 会话是从看板通过「打开会话」跳转进来的（`session.open` 由看板桥触发）；
  2. 当前会话就是被打开的那个会话；
  3. 左侧栏处于**收起/rail** 状态（展开时侧栏已有「看板」入口，不再重复）。
- 气泡位置：`conversation.input.dock`（Composer 上方），胶囊形，board 图标 +「返回看板」；**水平右边缘与输入框（`--dsh-composer-card-max-width` 卡片）右边缘对齐**，竖直方向保留 8px 间距。容器按 `max-width: calc(var(--dsh-composer-card-max-width) + 2 * var(--dsh-composer-side-clearance))` 居中、左右 padding = `--dsh-composer-side-clearance`，从而在不同窗口宽度下都不偏移。
- 样式：`border-radius:999px` + `corner-shape:round`、layer-2 底 + elevation-soft；不遮挡输入区，不改变 Composer 布局高度（dock 自带内边距）。
- 点击：回到看板面板，保留上次看板视图/筛选；气泡消失。切回看板或手动选择其他会话后自动清理状态。
- **来源高亮**：点击气泡时把 sessionId 写入 `sessionStorage`；看板挂载后按 session 找到对应卡片，滚动到可见区域并高亮 **1.8s**（business 蓝描边 + 背景淡闪，结束后自动清除）。`prefers-reduced-motion` 下改为静态描边、不做闪烁；列表视图对行使用同一语义。
- 从看板内启动「开始推进」但未打开会话时不出现；standalone 或宿主无面板桥时不出现。
- 键盘可达（focus-visible 与现有按钮一致）；不做常驻头部按钮，避免每个会话都多一个无关入口。
- 验收：1280/1440/1920 三档宽度下，气泡右边缘与输入框右边缘误差 ≤1px；返回后高亮卡片必须是来源卡；1.8s 后高亮消失；reduced-motion 下无动画。

### 7.14 待办回复语义

- 待办卡片回复只写入会话与时间线，**不自动移列、不自动开始执行**；Composer 提示固定文案见 §2.8。
- `needs_you` 讨论回复仍按审批/讨论规则移入进行中；`running` 回复只追加消息；`done` 回复不改状态。
- 任何「回复改变状态」必须由会话工具或显式开始推进触发，不能靠本地化文本或隐式规则判断。

### 7.15 新建卡片：工作区/目录与会话建议

- 入口不变：看板列头 `+` / 列表 toolbar「新建卡片」；表单先标题/摘要，再「工作区与目录」「关联会话」两组建议字段。
- 工作区切换：回填 cwd（工作区根目录）与项目建议；项目选项排序 = 当前工作区 → 最近使用 → 名称；切换工作区会重建目录 chips 与会话建议，不保留上一个工作区的会话选择。
- 目录：输入框可编辑；chips 写入 cwd；清空 cwd 时提交聚焦并提示「先选择执行目录」。
- 会话：新建置顶；进行中目标默认新建并选中「默认」；已有推荐会话显示「推荐」徽标，运行中显示「运行中」；选中行显示业务蓝描边。改选已有会话后提交为「创建卡片并绑定」。
- 提交：进行中新建 → 卡片直接进入进行中、会话 running、追加启动节点；已有会话 → 卡片绑定并保留目标列状态；独立预览只模拟、不调用宿主。
- 移动端：表单为底部弹层，字段单列/两列自动换行；chips、会话行、主按钮热区 ≥44px。

### 7.16 详情抽屉：无会话补建

- 无会话卡片：在标题/摘要下显示警示条（running 为橙黄，其他为中性）；下接「新建会话」内联表单，顺序固定为工作区 → cwd → 推荐目录 chips → 主按钮。
- 文案：running「卡片正在进行中，但没有绑定会话」/「状态和消息暂时无法回写；先选择工作区/目录，再创建会话。」；其他「这张卡片还没有绑定会话」/「先选择工作区/目录，再创建会话；创建后才会开始执行。」
- 按钮：running「创建并开始处理」，其他「创建并绑定」；创建前不显示会话 tab 与回复 composer；创建成功后再出现会话列表，可继续回复/审批。
- 独立预览：模拟创建会话并追加节点，toast 明确「（预览模式）」；生产如果宿主桥创建失败，回滚 `noSession` 状态并保留表单输入。
- 空态：没有工作区时禁用创建并提示先添加工作区；cwd 为空时聚焦输入框，不提交。

### 7.17 加载 / 空 / 错误

- 首次加载骨架卡；SSE 断连错误条；空列/空分组说明“这里会出现什么”并给下一步；筛选无结果提供清除筛选。
- 受阻/失败在待你确认列显示原因和重试；禁止只靠颜色表达状态。

## 8. 无障碍与国际化

- 文案全部走 locale 字典（含 `aria-label`、placeholder、Toast、空态、计数标签）；建议 key：`kanban.header.unarchived`、`kanban.header.needsCount`、`kanban.session.runningCount`、`kanban.approval.*`、`kanban.approval.submitAll`、`kanban.approval.questionIndex`、`kanban.session.primary`、`kanban.list.groupBy.*`、`kanban.done.showAll`、`kanban.dirty.confirm`、`kanban.theme.follow|light|dark`、`kanban.action.details`。
- 不用本地化文本做逻辑判断：状态、列、分组、优先级用稳定枚举。
- 图标按钮必须有 `aria-label`；装饰图标 `aria-hidden`；选项 fieldset/legend、备注有 label；抽屉/弹层 `role=dialog aria-modal aria-labelledby`。
- 状态不只颜色；审批按钮/选项有文字；计数有 title；卡片 `aria-label` 汇总标题、状态、优先级、项目。
- 焦点可见、焦点圈定与归还、reduced-motion、触控热区（主决策 ≥44）必须保留。

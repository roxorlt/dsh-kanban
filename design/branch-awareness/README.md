# 分支可视化 · 面向非技术用户的表达方案（原型 v0.1）

> 背景：卡片 `card-6f4b3d72` 的 Fork 风格提交图（v0.14.0）解决了「图形化」，但反馈提到出发点是**不懂代码的人也能看懂**。
> 本目录是四个表达方案的可视化原型，用于讨论后再排期实现；不含产品代码。

打开方式：

- 直接用浏览器打开 [`prototype.html`](prototype.html)（单文件，内含 4 个方案和术语对照）；
- 或看 `screens/` 下的截图：`00-overview.png`（全页）、`header-concepts.png`、`v1-card-badge.png`、`v2-branch-overview.png`、`v3-worktree-map.png`、`v4-drawer-plain.png`。

## 统一用词（先翻译，再展示）

| 代码里的词 | 给人看的说法 |
| --- | --- |
| 分支 / branch | **工作线**（一条独立改动线，不影响主线） |
| 主分支 / main | **主线**（大家共用的主版本） |
| 远端 / origin / GitHub | **线上**（别人能看到的那一份） |
| 提交 / commit | **改动**（「多 3 处改动」） |
| ahead / behind | **多 N 处 / 少 N 处** |
| merge | **并入主线** |
| worktree | **工作副本**（同一个项目的另一个文件夹） |
| dirty | **有未保存改动** |

## 四个方案

### 方案 1：卡片上直接写「工作线状态」（`v1-card-badge.png`）

看板卡片 / 列表行上加一行：`工作线 fix/approval-stuck · 比主线多 3 处改动 · 还没同步线上`。

- 优点：零点击成本，看板、列表、搜索里都能用；对非技术用户最直观。
- 代价：卡片多一行信息；需要「卡片 ↔ 工作线」的绑定数据。
- 状态色：进行中（蓝）/ 已并入主线（绿）/ 停滞或落后（橙）。

### 方案 2：看板顶部「工作线总览」（`v2-branch-overview.png`）

看板顶部一块可折叠面板：每条工作线一行，显示

- 工作线名 + 状态（进行中 / 已并入主线 / 停滞）
- 进度条 +「比主线多 3 处 · 少 0 处」
- 线上状态（已同步 / 还没同步）
- 工作副本位置、关联卡片数、最近改动时间

点一条工作线 → 看板只显示这条线的卡片；「按卡片」切回原视图。

- 优点：一次看清所有线在跑什么，最贴合「多张卡片分属不同分支」的原始痛点。
- 数据前提：卡片 ↔ 工作线映射 + v0.14 已有的 git 数据。

### 方案 3：「并行工作区」地图（`v3-worktree-map.png`）

按文件夹列出所有工作副本：主文件夹 / `.worktrees/feat-xxx`，每个显示

- 检出的工作线、正在跑的卡片、会话
- 有未保存改动 / 可以安全合入 / 可删除工作副本

- 优点：回答「同时开了几个文件夹、哪个任务在哪」；worktree 场景专用。
- 数据：git worktree 列表 + 卡片 cwd / 会话 cwd（现有接口已有）。

### 方案 4：详情抽屉「先说人话，图作为进阶」（`v4-drawer-plain.png`）

不改 v0.14 的提交图，只在它上面加一段一句话总结和一张状态表：

> 这张卡片在「feat/branch-badge」工作线上：比主线多 3 处改动，还没同步到线上；主线在那之后又有 1 处改动没并进来。

下面表格：在哪条线 / 和主线比 / 和线上比 / 什么时候算做完 / 其它工作线；提交图折叠在「进阶」里。

- 优点：非技术用户先拿到结论，专业用户仍可展开图；只改前端文案与顺序，数据已具备。
- 代价：几乎没有，属于最低风险的落地项。

## 建议落地顺序

1. **方案 4**（改写详情抽屉文案与顺序）——只改前端，立刻见效；
2. **方案 1**（卡片徽标）——需补「agent 开始推进时把工作线写到卡片」；
3. **方案 2**（工作线总览）——解决多卡片、多条线的总览；
4. 方案 3 作为进阶的「并行工作区」面板。

共同前提：**卡片要显式记录所属工作线**（现在只能靠 cwd / 会话目录推断），建议在 agent 工具里加字段并在开始推进时写入。

## 与现有实现的关系

- v0.14.0 的详情抽屉 Fork 图保留为「进阶视图」，本目录方案 4 是它上面的信息层；
- 方案 1/2/3 都需要新增看板级数据聚合（按工作线分组），不涉及改 `data.json` 结构（工作线记录在卡片字段上即可）。
